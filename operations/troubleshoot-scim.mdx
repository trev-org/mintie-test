<Warning>
  SCIM 2.0 is still in development. This runbook describes the planned
  operating flow for the [SCIM interface](/provisioning/scim).
</Warning>

## Start in the identity provider

Find the failed provisioning event and record:

- The operation: create, update, deactivate, or group membership change
- The affected user or group
- The HTTP status and response body
- The attempt time and provider event ID
- Whether retries are still running

Do not paste the SCIM bearer token into tickets or logs.

## Check the connection

1. Confirm the base URL is exactly `https://app.mintie.example/scim/v2`.
2. Verify the bearer token belongs to the same Mintie organization.
3. Check that the token has not been replaced or revoked.
4. Confirm the user or group is assigned to the provisioning application.
5. Retry one test operation instead of restarting a full synchronization.

## Diagnose by symptom

| Symptom | Check |
| --- | --- |
| Authentication fails | Bearer-token value, accidental whitespace, token organization, and token status |
| Create fails | Required email value, uniqueness, and IdP attribute mapping |
| Update reaches the wrong record | Stored Mintie resource ID and IdP external identifier |
| Deactivated user still has access | Provider event result, target user ID, and whether the IdP sent `PATCH active: false` or `DELETE` |
| Group membership is missing | Group assignment, push-groups configuration, and operation order |
| Same operation keeps retrying | First failure response; later retries often hide the original cause |

<Note>
  `DELETE /Users/{id}` is a soft delete. Mintie preserves the user row for
  audit purposes, marks it deactivated, and revokes its sessions.
</Note>

## Safe end-to-end test

<Steps>
  <Step title="Create a dedicated test user">
    Use a unique address that cannot collide with an employee account.
  </Step>
  <Step title="Update one mapped attribute">
    Change a name or test-group membership and confirm the same Mintie user is
    updated rather than duplicated.
  </Step>
  <Step title="Deactivate the user">
    Confirm the IdP operation succeeds and the user can no longer start a new
    Mintie session.
  </Step>
  <Step title="Remove test data">
    Keep the provider event IDs and timestamps, but remove temporary group
    assignments and revoke any test credentials.
  </Step>
</Steps>

## Escalate

Send support the Mintie organization, provider name, operation, resource ID, event ID, timestamp with time zone, and redacted response. Never include the `Authorization` header.
