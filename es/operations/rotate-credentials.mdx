---
title: "Rotar credenciales"
description: "Sustituye las credenciales de identidad sin interrumpir el acceso"
groups: ["enterprise"]
---

Rota las credenciales antes de que caduquen, cuando un administrador deje la organización o siempre que se sospeche una exposición. Trata una rotación no planificada como un incidente y utiliza el [procedimiento de respuesta a incidentes](/es/operations/incident-response).

## Inventario

| Credencial | Dónde se almacena o gestiona | Método de validación |
| --- | --- | --- |
| Certificado de firma SAML | Metadatos del proveedor de identidad | Inicio de sesión de prueba |
| Secreto de cliente OIDC | Aplicación del IdP y conexión de Mintie | Inicio de sesión de prueba |
| Token bearer de SCIM | Aplicación de aprovisionamiento del IdP y Mintie | Ciclo de vida de un usuario de prueba |
| Clave de API de Mintie | Aplicación que realiza las llamadas | Una solicitud de API de solo lectura |

No incluyas nunca el valor de un secreto en un ticket, mensaje de chat, captura de pantalla o procedimiento operativo del equipo.

## Antes de cualquier rotación

- Asigna a una persona la actualización del IdP y a otra la validación de Mintie.
- Registra al responsable de la credencial, su caducidad, el entorno afectado y la ventana de reversión.
- Confirma que haya disponible una sesión activa de administrador.
- Pausa los cambios no relacionados hasta que termine la validación.

## Certificado de firma SAML

1. Añade o activa el nuevo certificado en tu IdP.
2. Actualiza los metadatos que utiliza la conexión de Mintie. Si los controles de autoservicio no están disponibles, coordina la actualización con el soporte de Mintie.
3. Ejecuta inicios de sesión de prueba para un administrador y un miembro estándar.
4. Retira el certificado anterior solo después de que ambas pruebas funcionen.

<Tip>
  Es más fácil mantener actualizada una URL de metadatos que un archivo XML
  subido, pero aun así debes realizar una prueba inmediatamente después de que
  el IdP cambie su certificado activo.
</Tip>

## Secreto de cliente OIDC

1. Crea un secreto de sustitución en la misma aplicación OIDC.
2. Actualiza la conexión de Mintie con el nuevo valor.
3. Ejecuta **Test sign-in** en una ventana privada del navegador.
4. Revoca el secreto anterior cuando la prueba se complete correctamente.

Si tu IdP solo permite un secreto activo, programa una ventana de mantenimiento y asegúrate de que ambos administradores estén presentes.

## Token SCIM

<Warning>
  La generación y la rotación de tokens SCIM dependen de los controles de
  administración de SCIM previstos. Sigue esta secuencia cuando dichos
  controles estén disponibles.
</Warning>

1. Genera un token de sustitución en **Configuración → Autenticación → SSO → SCIM**.
2. Actualiza el token en la aplicación de aprovisionamiento de tu IdP.
3. Crea o actualiza un usuario dedicado para pruebas.
4. Revoca el token anterior y confirma que no haya reintentos pendientes.

## Clave de API

1. Crea una clave de sustitución para el usuario o la cuenta de servicio correctos.
2. Despliégala mediante tu gestor de secretos.
3. Verifica una solicitud de bajo riesgo en cada entorno afectado.
4. Revoca la clave anterior y supervisa las respuestas `401`.

Después de la rotación, registra quién la completó, cuándo se revocó la credencial anterior y la fecha de la próxima rotación prevista, pero nunca el secreto en sí.
