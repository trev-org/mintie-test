## Qué te aporta SCIM

Cuando tu IdP envía un evento del ciclo de vida del usuario (nueva contratación, cambio de grupo, desaprovisión), Mintie lo refleja en segundos, sin clics del administrador.

## Endpoints

La URL base es `https://app.mintie.example/scim/v2`.

| Método | Ruta | Propósito |
| --- | --- | --- |
| `GET` | `/Users` | Lista usuarios |
| `POST` | `/Users` | Crea un usuario |
| `GET` | `/Users/{id}` | Obtiene un usuario |
| `PATCH` | `/Users/{id}` | Actualiza un usuario (incluido el toggle de activación) |
| `DELETE` | `/Users/{id}` | Borrado lógico de un usuario |
| `GET` | `/Groups` | Lista grupos |
| `POST` | `/Groups` | Crea un grupo |
| `GET` | `/Groups/{id}` | Obtiene un grupo |
| `PATCH` | `/Groups/{id}` | Actualiza un grupo (nombre y pertenencia) |
| `PUT` | `/Groups/{id}` | Reemplaza un grupo |
| `DELETE` | `/Groups/{id}` | Borrado lógico de un grupo |

### Operaciones PATCH de Groups

`PATCH /Groups/{id}` acepta las operaciones estándar de SCIM 2.0 sobre el atributo `members`:

| Op | Efecto |
| --- | --- |
| `add` | Agrega los usuarios indicados al grupo. |
| `remove` | Quita los usuarios indicados del grupo. Admite una ruta filtrada (`members[value eq "<userId>"]`) o una lista de valores en `members`. |
| `replace` | Reemplaza todo el conjunto de miembros por la lista proporcionada. |

Cada cambio de pertenencia dispara un recálculo del rol de cada usuario afectado. Consulta [Mapeo de grupos a roles](/es/provisioning/group-role-mapping) para ver cómo se resuelven las pertenencias en roles de Mintie.

## Autenticación

Un token bearer por organización. Genera y rota el token desde la [UI de administración](/es/setup/enable-sso) una vez se publique.

```http
Authorization: Bearer scim_live_<token>
```

<Note>
  Los tokens SCIM tienen alcance a una organización y a un único propósito. No pueden leer ni
  escribir nada fuera de los endpoints SCIM.
</Note>

## Semántica del borrado lógico

`DELETE /Users/{id}` **no** elimina la fila. Establece `deactivated_at = now()` y revoca todas las sesiones. La fila se conserva para fines de auditoría.

`DELETE /Groups/{id}` se comporta igual. La fila del grupo se conserva con `deactivated_at = now()`, se limpia su lista de miembros y se recalcula el rol efectivo de cada usuario que pertenecía al grupo. Eliminar un grupo nunca elimina a sus miembros.

Consulta [registros de auditoría](/es/security/audit-logs) para ver los eventos que emiten estas operaciones, incluidos `scim.group.provisioned` y `scim.group.membership_changed`.

## Conformidad

El endpoint SCIM apunta a la compatibilidad con la suite de cumplimiento SCIM de Okta. Una vez disponible, el SCIM de Mintie se podrá probar con:

- El probador SCIM de Okta
- El agente de aprovisionamiento de Microsoft Entra ID
- WorkOS Directory Sync (usado internamente)

## Lo que harás

<Steps>
  <Step title="Genera un token SCIM">
    Desde **Configuración → Autenticación → SSO → SCIM**, haz clic en **Generar token**.
  </Step>
  <Step title="Configura tu IdP">
    Pega la URL base y el token en la configuración de aprovisionamiento SCIM de tu IdP.
  </Step>
  <Step title="Elige los mapeos de atributos">
    Los valores predeterminados coinciden con SCIM Core estándar. Mapea cualquier atributo personalizado que
    tu organización necesite.
  </Step>
  <Step title="Envía un usuario de prueba">
    Aprovisiona un usuario desde el IdP y confirma que aparece en Mintie.
  </Step>
</Steps>
