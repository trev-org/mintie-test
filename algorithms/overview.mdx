The algorithm catalog collects 10 common coding problems and 10 reusable algorithm patterns. Every solution is a TypeScript implementation backed by automated tests, so the code on each page is the same code that passes those tests.

Use the catalog to study a technique, prepare for coding interviews, or find a reference implementation for a familiar problem.

## Patterns

| Pattern | Summary |
| --- | --- |
| [Binary search](/algorithms/patterns/binary-search) | Repeatedly discard half of an ordered search space. |
| [Complexity analysis](/algorithms/patterns/complexity-analysis) | Describe how runtime and auxiliary memory grow as input size increases. |
| [Dynamic programming](/algorithms/patterns/dynamic-programming) | Reuse solutions to overlapping subproblems instead of recomputing them. |
| [Graph traversal](/algorithms/patterns/graph-traversal) | Explore connected vertices with a queue or stack while preventing duplicate work. |
| [Greedy one-pass scans](/algorithms/patterns/greedy-scans) | Maintain the best local state needed to make each next decision. |
| [Hash maps](/algorithms/patterns/hash-maps) | Store values by key for expected constant-time membership and lookup. |
| [Linked lists](/algorithms/patterns/linked-lists) | Traverse and reconnect nodes without moving the values they contain. |
| [Stacks](/algorithms/patterns/stacks) | Process nested or most-recent state in last-in, first-out order. |
| [Tree traversal](/algorithms/patterns/tree-traversal) | Visit every node through recursive or iterative depth-first or breadth-first traversal. |
| [Two pointers](/algorithms/patterns/two-pointers) | Move two indexes through a sequence while maintaining a useful relationship. |
